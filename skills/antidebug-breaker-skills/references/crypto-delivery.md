# 加密逆向交付说明

此文件定义成果如何使用与验证，不规定分析方法。以用户给出的接口、参数和目的确定复现范围；没有要求响应解密时，不额外强制逆向所有响应。

## 报告需要让用户知道什么

- 用户要求的目标与输入输出：参数计算任务说明函数、参数和返回值；接口复现任务再说明 URL/方法、字段位置以及明文输入与传输值的关系。
- 已确认的变换：序列化、编码、加密、摘要或签名的顺序；与实际算法有关的模式、填充、字符编码、密钥/IV/nonce 来源，以及时间戳、会话等依赖。只列与目标有关的内容。
- 定位证据：来源 JS URL/文件和函数、位置或可检索片段；必要时附对应输入输出样本。库名或 Hook 标签是线索，不能独立证明目标接口使用了该算法。
- 交付文件、配置、依赖和启动命令；哪些已实际验证，哪些仍是推断或受运行条件限制。

运行原始 JS 引擎可以是有用的参考实现或阶段成果，应说明仍依赖的源文件及未解释的目标逻辑，不能把引擎可运行等同于已经理解算法或完成独立实现。最终交付是否达标，仍按用户要求的语言、形态与目标范围判断；未另行指定时采用默认 Python 交付。

随机性、时间戳、环境值和会话密钥等关键依赖，应说明来源及判断依据；尚未证实的原因标为推断。输出变化、本地环境缺少某字段或代码混淆复杂，都不能单独证明随机算法、必须登录或无法本地实现。以依赖缺失或实现困难为由结束时，应给出具体阻塞证据及继续所需条件，不将尚未解决写成不可实现。

摘要、编码、签名和加密不要混称。例如单向摘要通常不能“解密”，应复现它的输入构造与计算。复现既有协议时匹配实际算法，不擅自替换成另一种算法或填充。

## 默认交付：纯本地 Python 复现脚本

按用户范围交付：只要求加密、解密或签名参数计算时，提供对应函数、运行示例和验证结果，无需增加登录或 HTTP 请求；要求接口复现时，再完成从业务输入到请求参数的本地生成及 HTTP 请求。交付范围内的算法与依赖应足以独立运行，不能每次让浏览器替脚本算签名或密文。Python 加密库及网络库可以按实际需要选择。

将交付范围内需要更换的业务参数、密钥以及涉及请求时的地址、凭据和会话值作为配置或输入。确实固定的协议常量可以保留；动态时间戳、随机量、会话密钥等按协议生成、获取或由明确的输入提供，不能把抓到的一次请求当作通用实现。报告不必公开实际凭据或私钥，说明来源与配置位置即可。

随脚本提供实际需要的依赖声明、运行命令和输入示例。文件数量及文件名自由，例如一个 `client.py` 与依赖文件已足够时，无需搭建服务或工程框架。

若目前只能完成浏览器辅助计算，应继续寻找本地实现。纯本地复现是交付要求，不保证每个目标在现有条件下都可实现；确实未能解决时，按 [通用收尾](../SKILL.md#通用收尾) 交代阻塞依据和继续所需条件，交付已确认的逻辑和有用成果，不擅自将浏览器自动化包装成达标脚本。

## 双层 mitmproxy 的成果形态

典型链路如下；端口、工具和文件组织可按目标调整。Burp 也可换成用户指定的明文查看/修改代理。

```text
浏览器 ⇄ 下游 mitmproxy ⇄ Burp 等明文代理 ⇄ 上游 mitmproxy ⇄ 目标服务
```

| 位置 | 请求方向 | 响应方向 |
| --- | --- | --- |
| 下游：靠近浏览器 | 将目标加密字段还原为可编辑明文，或取得与该请求匹配的加密前明文 | 将中间明文还原成浏览器实际期望的格式 |
| 上游：靠近目标服务 | 将编辑后的明文按真实协议重新加密，并重算受影响的摘要/签名 | 将目标响应按已确认逻辑转换成中间明文 |

只转换目标协议需要处理的方向及字段，其余直通。双层是两个代理角色，不要求每个方向都存在加密。HTTPS/TLS 解包也不等同于解开应用层密文。

交付通常包含 `downstream.py`、`upstream.py` 和必要的公共算法模块。需要额外 Hook、桥接服务或配置时一并提供，说明明文如何进入链路。给出实际监听地址/端口、各代理的串联设置、启动命令及 HTTPS 所需的证书信任配置，避免循环指向。

脚本应限定目标主机、路径/方法及字段；目标以外的数据保持原样。目标数据转换失败或找不到关联明文时，明确报告本次明文处理失败，不得发送中间态或部分转换的数据。确认用户未编辑请求，且能完整保留或恢复原始密文请求时，可以原包直通；已经编辑或无法保证完整恢复时阻断，不能把中间明文误当合法密文发往服务端。

修改内容时保留协议要求的封装、序列化与编码，并处理受影响的签名、长度或相关字段。请求与响应需要共享密钥或上下文时，关联到对应会话和请求，不能让不同请求覆盖一个全局“最新值”。

## 非对称场景：说明明文从哪里来

参考文章中的 RSA 场景通过 Hook 取得加密前明文，再使用服务器公钥重新加密。它不需要、也没有推导服务器私钥。报告应准确称为“捕获加密前明文并重新加密”，不能声称“用公钥解密了原密文”。

明文可由实际掌握的解密能力、加密前观测或其他已验证机制取得，自行选择适合现场的方式。说明各方向的密钥角色、算法及填充，不能把某个 JSEncrypt 案例等同于全部非对称协议。

如果采用明文旁路桥接，交付需要可靠地关联调用、密文字段、请求及会话。可以采用密文与上下文映射、请求标识等方案；不要照搬“全局数组依次取第一个、第二个值后清空”的假设。并发、多字段、后台请求、重复调用或相同明文都可能打乱次序。映射歧义或过期时明确本次明文处理失败，不能猜配；请求是否原包直通或阻断，遵循上面的完整恢复条件。

旁路服务需要时才创建，默认仅本地可达并校验其调用方；关联元数据不要留进发往目标的请求。所用 Hook、传输机制和维护方式自由选择，不强制 Flask、同步 XHR、GET 查询参数或某个插件。

## 用实际结果支撑交付

验证方式随协议选择，报告至少给出已执行的验证及结果，区分计算结果一致、请求已发送、验签通过和业务成功。只有离线样本验证时明确说明；HTTP 200、路由错误、限流或未出现签名错误，均不能单独证明验签通过或业务接受。没有确认服务端检查顺序时，不据业务错误反推验签已经完成。这些是不同结论的证据边界，不要求参数计算任务额外进行在线请求。

说明验证覆盖的输入、环境或协议分支，以及尚未覆盖的关键差异；单一环境、请求方式或标志位取值的结果不能泛化为全部情况。保留可复核的输入、必要上下文和预期输出，或给出等效证据及样本、测试文件的位置，并说明对照值来自实际观测、参考实现还是其他来源；仅由待验证实现生成的预期值不能证明它与目标一致。报告中的示例、长度、公式和验证范围应相互一致；脱敏后无法重算的示例应注明其用途。

确定性算法可对比已知输入输出。含随机填充、IV 或 nonce 的算法不要求新密文逐字等于抓包值，应验证解密结果、协议约束或服务端实际处理结果。不要通过固定随机数让对比通过，却破坏真实协议。

双层方案需要说明两个结果：中间层是否能看到/修改明文，浏览器与服务端是否仍按预期工作。有上下文桥接时，覆盖实际支持的并发或多字段情况，不能只凭单次打印明文就声称链路完成。
