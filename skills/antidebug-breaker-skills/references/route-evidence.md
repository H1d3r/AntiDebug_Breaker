# 路由结果与来源

目标是发现并定位用户关心的 Vue/React 隐藏动态路由。可分析源码、运行时、懒加载资源、接口数据或组合使用其他办法，不要求先运行插件、修改路由器或逐个访问路由。

## 可核查的结果

报告以路由和来源为主体；下面是可用字段，不要求固定表格或额外文件格式：

| 信息 | 内容 |
| --- | --- |
| 路由 | 完整路径或保留参数的模式，例如 `/users/:id`；必要时标明父路由、别名、basename/hash 前缀 |
| 来源 | JS URL/文件，配合函数、行列、模块 ID 或可检索片段；source map 位置应与生成文件位置区分 |
| 证据状态 | 路由定义、静态候选、运行时已注册、已验证访问等实际获得的证据；不强制为所有条目补齐所有状态 |
| 插件对比 | 基线中已存在、基线中未捕获，或未对比 |
| 条件 | 已知的角色、功能开关、懒加载、菜单接口、注册时机等；未知时如实说明 |

路径去重时保留不同来源、实例和条件。嵌套路由按真实路由语义组合，不能把绝对子路径错误拼到父路径后；保留动态参数和通配符，不猜出一批具体页面。

有些动态路由由接口下发，再由 JS 拼接或注册。此时同时标出数据来源接口与负责转换/注册的 JS；若无法定位某部分，说明未知。内联脚本或 eval 源按实际来源记录，不为满足“哪个 JS”而虚构文件。

菜单链接、组件名、文件路径或任意字符串可作为线索，但不能直接当成已注册路由。仅返回 SPA 外壳的 HTTP 200、绕过前端跳转或手动注册路由，也不证明原始页面已注册该路由或后端允许其数据访问。

## “插件未捕获”的含义

差异基线可以来自本次插件输出、用户提供的导出或先前记录；记录足以解释差异的页面、登录/角色状态、采集时点和有效性。比较时区分页面已加载的原始路由与本次修改/补注册后才出现的路由。

采集状态正常、未过期且目标页面/状态可确认的空快照（`routes: []`），可以作为本次未捕获的比较基线，但不能证明全站不存在路由。未开启采集脚本、超时、内容脚本不可用或缓存过期得到的空结果，不能视为有效空快照。无法确认有效性时标为对比条件不足；没有可用基线时继续收集并交付来源，说明未与插件比较。

“插件未捕获”只描述相对本次基线的差异，并不自动证明插件缺陷。未加载资源、角色不同、接口未下发、动态注册未触发都可能导致差异。最终范围对应已检查的资源和状态，避免承诺找全网站所有角色、所有版本的路由。

## 可借鉴的线索

用户提供的《最大化获取Vue框架SPA类型下的路由》（2025-10-09，0xsdeo）强调已注册路由与尚未加载/添加路由的差异、多个应用/路由实例，以及前端导航守卫与路由定义的区别。源码中未执行的路由表、动态导入、注册调用、接口返回的路由/菜单数据都可能提供补充证据，自行判断哪些值得分析。

文章中的 `addRoute`、构造路由器时补充路由、替换 JS、修改白名单等是特定场景的手段，不是收集路由的先决条件。清除导航守卫可能同时阻止动态路由注册或初始化；停掉跳转并不使未加载路由自动出现。

Vue 与 React 的可用结构取决于实际框架/路由器与版本。不要把 Vue 的实例方法套到 React，也不要把 React Fiber 或菜单候选等同于完整路由表。
